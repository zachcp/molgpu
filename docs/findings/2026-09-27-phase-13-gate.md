## Contract notes

- Multi-stage providers (`<Superpose>`, `<Unwrap>`) use a new internal
  `CoordinatePasses`. It encodes every stage into one command buffer per content
  generation and submits it during render. The submission therefore lands after
  the upstream dispatch and before any descendant's. This is how the plan's
  "same upstream generation, in order, no readback" holds.
- `<Superpose>` treats a live frame as collinear when the sum of its scatter's
  2×2 minors is below 1e-6·trace². That is about 1e-6 of the trace for the
  middle eigenvalue, looser than the CPU's 1e-8, because the solve is in f32.
  Such a frame passes through silently.
- `<Unwrap>` holds two 16-byte link buffers per atom for pointer jumping. Its
  lattice search stops at 4096 candidates and reports `search-limit` where the
  CPU throws. The browser test does not reach that path.

## Budgets

`deno task gate:dynamics` mounts root → `<Trajectory>` (four slots) → `<Unwrap>`
→ `<Superpose to="first">` (a full-size reference) → `<NormalMode>` at 100k and
1M atoms. The atoms are ten-atom covalent chains in a periodic box. Memory is
owned GPU bytes by label, from the viewer's instrumentation. The shared cell
list is not mounted in this scene, so it is added from `planCellList` for an 8 Å
cutoff. "Within a generation" means buffers that only the passes of one
generation read (unwrap links, fit state, params, status staging). They stay
allocated for reuse. Headless Chrome, Apple M1, decimal MB.

|                                     |     100k |      Budget |        1M |     Budget |
| ----------------------------------- | -------: | ----------: | --------: | ---------: |
| Persistent (with cell list)         | 14.72 MB |       32 MB | 147.22 MB |     224 MB |
| Within a generation (+ cell list)   |  3.27 MB |       16 MB |  32.71 MB |      96 MB |
| Frames until a changed generation   |        1 |           3 |         1 |          — |
| Full-frame traffic (read + written) |  44.4 MB | ≥ 9.6 plain |  444.0 MB | ≥ 96 plain |
| Timeline-tick traffic (mode only)   |   4.0 MB |             |   40.0 MB |            |

At 1M atoms the persistent memory breaks down as follows:

- Root positions and radii: 16 MB.
- Frame window: 48 MB.
- Four provider outputs: 48 MB.
- Superpose reference: 12 MB.
- Normal-mode map and vectors: 5.2 MB.
- Unwrap forest (parent and component): 8 MB.
- Component shifts: 1.6 MB.
- Cell list: 8.4 MB.

The unwrap links (32 MB) make up almost all of the within-generation figure.

A timeline tick re-runs only `<NormalMode>`: the unwrap and superpose dispatch
counters do not move. A resident trajectory frame runs each multi-stage provider
exactly once. From the state change, the new generation publishes on the next
animation frame, and at both sizes the GPU work is done 3–22 ms later, bounded
by display cadence.

**Traffic exceeds the plan's four-plain-pass baseline, as the plan asked to
report.** A full frame reads and writes about 444 bytes per atom:

- Trajectory lerp: 36 B.
- Unwrap: link 44 B, four pointer-jumping rounds of 48 B each for depth-9
  chains, and placement 60 B.
- Superpose: centroid and covariance reductions 48 B, then apply 24 B.
- Normal mode: 40 B.

The rounds grow as `ceil(log2(depth))`. A long polymer at 1M atoms adds about 48
MB per round. Follow-up `9g3.11` covers this.

  through a status callback like `<Unwrap onStatus>`.
