## Native compute compatibility

Reviewed exact rc.3 `compute/kernel.mjs`, `queue/dispatch.mjs` and
`pass/compute-pass.mjs`. Dispatch still emits `computePre`/`computePost`,
withholds work while the async pipeline is absent or stale, and invokes
`countDispatch` only for an unsuppressed dispatch. ComputePass still encodes
these callbacks and submits synchronously. The existing observation wrapper
preserves the phase and publishes via a microtask after submission; this does
not imply GPU completion. No runtime compatibility change was needed; the source
pin comment now names rc.3. Replacement/readback/retirement acceptance is tested
separately.

## Follow-up: explicit Math entry and config imports

The user requested a find/replace audit of missing declarations and the direct
Math module. Molecular interpolation already used `@use-gpu/math` rather than
Core. However, the bare Math alias selected its CommonJS main under Deno:
`import { catmullRomWeighted } from "@use-gpu/math"` failed with a missing named
export. The function exists in the exact candidate's ESM entry.

Root, viewer, timeline and hardening-fixture Deno mappings now direct the bare
Math alias to `npm:/@use-gpu/math@0.21.0-rc.3/mjs/index.mjs`. Timeline and tube
geometry use the bare alias; package unfurling still emits the same exact ESM
URL. The isolated consumer configuration uses that mapping too. Direct Deno Math
import now succeeds (`catmullRomWeighted` is a function; `lerp(1, 3, .5)` is 2).
The remaining Frame context and event imports already use Frame.

Seven Vite fixture configs now use `fileURLToPath` from `node:url`, replacing
the unresolved `@std/path` config import. Elastic, GPU DSSP, SES field and TSX
builds pass without the former warning. EField/trajectory/volume configs are
covered by their browser suites.

These changes do not edit upstream packages. Frame's undeclared Parse/Traits and
Workbench's undeclared Math remain properties of their distributed manifests, so
the scoped registry/local npm tree requirements remain. Direct Traits ESM import
interoperability is separate from the Math alias fix.
