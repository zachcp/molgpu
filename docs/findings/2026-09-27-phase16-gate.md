## Measured cost

| Atoms  | Model    | Grid | Time   | Pairs/s |
| ------ | -------- | ---- | ------ | ------- |
| 5 000  | distance | 128³ | 0.51 s | 2.0e10  |
| 50 000 | distance | 128³ | 5.5 s  | 1.9e10  |
| 50 000 | debye    | 128³ | 5.3 s  | 2.0e10  |

This is about a tenth of the counter-review's estimate. The kernel reads one
workgroup-memory vec4 per pair and evaluates one sample per invocation. Register
blocking and a smooth cutoff are follow-up egp.10. Interactive rates need about
≤ 3e8 pairs per generation. 1crn at the defaults (79k samples × 300 atoms) and
small ligand complexes qualify; 1a4y (2.3e9) recomputes at about 10 Hz.

## Invariants

  `@molgpu/fields` (`sampleVolumeGradientWgsl`) export strings and plain data.
  `VolumeGrid` in table is a type and validator. Hardening H1–H6 pass for every

  `VolumeContext`. The existing trajectory and coordinate suites pass.
- **CONCEPT 9:** `<Isosurface>`, `<VolumeSlice>` and `volumeSample()` run
  unchanged under `<EField>`. `useVolumeSnapshot()` returns a real `VolumeData`.

## Contract changes (documented)

- `VolumeContextValue` (advanced) changed shape, and `VolumeContext` now
  defaults to null. Leaving it required had broken every field colour outside a
  volume (Live throws on a missing required context). The existing components
  and volume suites caught this before commit.
- `volumeSample()` has an argument-free, GPU-first form. `evaluate` needs
  `{ volume }` for it.
- `<Surface color>` accepts position-only fields.
- Coordinate snapshots share `ThrottledReadback`; counters are unchanged.

READMEs, `api.txt`, CHANGELOGs, `DESIGN.md` (computed volumes) and `ROADMAP.md`
were updated.
